# 原生存储创建修复验证（2026-11-11）

这是候选修复记录，不是新镜像的正式发布或完整验收声明。

## 原因与修复

原生 Basic 创建调用 mdadm 的 `--bitmap=lockless`。原内核未启用
`CONFIG_MD_LLBITMAP`，写入 `bitmap_type=llbitmap` 返回 EINVAL。
在同一 X5 6.18 源码和其余配置不变的条件下，仅启用该选项，重新构建
Image、模块和 initramfs。镜像组装器现在检查 MD、RAID1、LLBITMAP 配置，
在组装前拒绝缺少原生创建能力的内核。

内核构建者应在既有 X5 配置上启用 `CONFIG_MD_LLBITMAP=y`，执行
`olddefconfig` 并核对配置差异，再生成匹配的 Image、模块和 initramfs。
不能只替换 Image 而保留不匹配的模块，也不能把旧发行镜像当成修复镜像。

候选 Image SHA-256：
`01bc5d3952965ee623c85c40ee183f7410841c213582809495039d9995a38de9`

候选配置 SHA-256：
`bee5f9981b13f72ea85374630a5545c0da58c776b51e57308bad36baac5ebf20`

## 实际验证

| 项目 | 结果 |
| --- | --- |
| 旧内核原生 Basic/Btrfs 创建 | 复现 EINVAL |
| 候选内核、替换板、120 GB USB 盘原生 Basic/Btrfs 创建 | 通过 |
| 普通用户 1 GiB 文件写入、fsync、SHA-256 回读 | 通过 |
| 请求清除文件缓存后的三遍回读 | 通过 |
| 正常关机、冷启动、120 GB 卷自动挂载与文件哈希 | 通过 |
| 16 GB USB 盘原生 Basic/ext4 创建 | 创建成功 |
| 16 GB 持续读写及冷启动后稳定性 | 未通过：USB 超时、重置、设备消失 |
| 仅对 16 GB 盘限制单次请求为 64 KiB | 未通过：USB 重置后写入报只读；临时规则已撤销 |
| 配置门禁单元回归 | 10 项通过，新增用例先在旧实现失败 |
| 完整通用候选镜像与重新刷机回归 | 尚未完成 |

16 GB 盘在 Mac 两遍全盘读取一致；Mac 写入测试由用户主动拔盘中断，
不能算作坏盘证据。X5 的 USB 问题需要盘、端口、传输条件的进一步隔离。
页面“存储空间已损坏/缺失硬盘”描述的是卷失联状态，并不能证明闪存物理损坏。

不要通过隐藏错误、强制挂载失联卷或把所有 USB 盘全局降速来宣称修复。
