# 原生存储创建修复验证（2026-11-11）

记录 v0.2.0 的 Basic 存储修复、同一内核的真板测试以及 r16 镜像回归范围。

## 原因与修复

原生 Basic 创建调用 mdadm 的 `--bitmap=lockless`。原内核未启用
`CONFIG_MD_LLBITMAP`，写入 `bitmap_type=llbitmap` 返回 EINVAL。
在同一 X5 6.18 源码和其余配置不变的条件下，仅启用该选项，重新构建
Image、模块和 initramfs。镜像组装器现在检查 MD、RAID1、LLBITMAP 配置，
在组装前拒绝缺少原生创建能力的内核。

内核构建者应在既有 X5 配置上启用 `CONFIG_MD_LLBITMAP=y`，执行
`olddefconfig` 并核对配置差异，再生成匹配的 Image、模块和 initramfs。
不能只替换 Image 而保留不匹配的模块，也不能把旧发行镜像当成修复镜像。

初版修复内核 Image SHA-256：
`01bc5d3952965ee623c85c40ee183f7410841c213582809495039d9995a38de9`

候选配置 SHA-256：

## 实际验证

| 项目 | 结果 |
| --- | --- |
| 旧内核原生 Basic/Btrfs 创建 | 复现 EINVAL |
| 候选内核、替换板、120 GB USB 盘原生 Basic/Btrfs 创建 | 通过 |
| 普通用户 1 GiB 文件写入、fsync、SHA-256 回读 | 通过 |
| 请求清除文件缓存后的三遍回读 | 通过 |
| 正常关机、冷启动、120 GB 卷自动挂载与文件哈希 | 通过 |
| 16 GB USB 盘原生 Basic/ext4 创建 | 创建成功 |
| 16 GB 持续读写及冷启动后稳定性 | 未通过：USB 超时、重置、设备消失 |
| 仅对 16 GB 盘限制单次请求为 64 KiB | 未通过：USB 重置后写入报只读；临时规则已撤销 |
| 配置门禁单元回归 | 10 项通过，新增用例先在旧实现失败 |
| r16 完整镜像与重新刷机回归 | 写入、全量回读、首启及已有 Basic 卷导入通过 |

16 GB 盘在 Mac 两遍全盘读取一致；Mac 写入测试由用户主动拔盘中断，
不能算作坏盘证据。X5 的 USB 问题需要盘、端口、传输条件的进一步隔离。
页面“存储空间已损坏/缺失硬盘”描述的是卷失联状态，并不能证明闪存物理损坏。

不要通过隐藏错误、强制挂载失联卷或把所有 USB 盘全局降速来宣称修复。

## 故障后的停机恢复补丁

16 GB 盘换 USB 3.0 端口后仍枚举失败；临时隔离原生探测服务和 RAID
自动组装后，盘同样在 USB 枚举阶段失败。因此没有把后台探测认定为根因。
临时隔离配置已撤销，正常服务已恢复。

同时，故障卷触发 `md_llbitmap_daemon_fn waiting for page ... timeout`，
关机在文件系统全部卸载、根分区只读后仍停在停止 MD 设备阶段。
当前源码缺少上游的超时引用恢复补丁，已准备回移：
[上游作者补丁](https://lists.openwall.net/linux-kernel/2026/01/23/1735)。
对应文件为 `fnos/patches/0005-md-llbitmap-resurrect-on-timeout.patch`。

`fnos/tests/llbitmap_timeout_regression.py <内核源码>/drivers/md/md-llbitmap.c`
提取真实函数，在指定构建服务器编译并模拟超时/成功两条分支。
旧源码失败、应用补丁后通过。这只是离线状态恢复回归，不是内核并发或
实际设备故障恢复验收。USB 设备的枚举故障仍待定位。storage-r15 候选镜像
未包含此补丁，storage-r16 已纳入。

## 内核 #5 真板复验

在替换板上部署包含上述补丁的 6.18.0 #5 后，以已清空的 120 GB USB 盘
从飞牛 Web 创建 Basic/Btrfs 存储空间。界面显示正常，
管理员写入并回读 128 MiB 测试文件。整机正常关机并重新上电后，卷自动
挂载在 `/vol3`，文件 SHA-256 与重启前相同。本次跳过界面可选的全盘
读写检测。

2 TB 东芝盘继续作为外置 ext4 使用。冷启动后自动挂载，文件系统 UUID
和三个 32 MiB 只读抽样的 SHA-256 与操作前一致。本次未对该盘执行格式化、
创建存储空间或写入测试。16 GB 盘已退出本次验收。

包含同一内核的完整镜像 storage-r16 已通过全量回读、干净首启、首次设置和已有 Basic 卷导入。上述新建卷和冷启动结果来自已安装系统上的内核更新。全新 r16 系统的首次创建、双盘 ext4 RAID1 与实际设备故障注入仍待实测。
